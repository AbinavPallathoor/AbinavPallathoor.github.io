# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Personal portfolio (abinav.is-a.dev): sections of project cards (Hardware, Gamedev, Software) that expand in place when clicked. Hardware cards show a 3D model on a turntable; Software (mobile app) cards show a CSS 3D phone that zooms into its screen recording; Gamedev cards show a CD jewel case that cross-fades into the trailer. Vite + TypeScript + three.js + GSAP (Flip, ScrollTo). No framework, no tests, no linter.

## Commands

- `npm run dev`: Vite dev server
- `npm run build`: `tsc --noEmit` type-check, then `vite build` into `dist/`. This is the only check there is, so run it after changes.
- `npm run preview`: serve the built `dist/`

Deploy: pushing to `main` runs `.github/workflows/deploy.yml` (Node 22, `npm ci && npm run build`, uploads `dist/` to GitHub Pages). There is no `vite.config`, so the base path is `/`; asset URLs are still built with `import.meta.env.BASE_URL` and should stay that way.

## Architecture

- `index.html` holds the static page shell (header, section headings, footer); `src/main.ts` builds the cards into `#hardware`, `#gamedev` and `#software` at runtime. `cardShell()` builds the shared card markup; each section fills the viewer differently.
- `src/projects.ts` is the hardware content: an array of `Project` objects, sorted newest first by `date` (`YYYY`, `YYYY/MM` or `YYYY/MM/DD`; a bare year sorts after that year's months; undated go last). `model.rotation` is degrees with y up (CAD exports are often z-up, hence `[-90, 0, 0]`), `model.scale` is relative to the auto-fit. `doc()` links point into `public/docs/`.
- `src/stage.ts` (`Stage`): **one shared offscreen WebGLRenderer** for all cards. Each card gets its own `Scene`/camera and a plain 2D `<canvas>`; every frame the renderer draws a card's scene into the bottom-left of the shared buffer and `drawImage`s it into that card's canvas. This keeps a single WebGL context while letting models live in normal DOM stacking (cards overlap during Flip animations). Models load lazily via `IntersectionObserver`, are centered and scaled to a unit bounding sphere, and decode with Draco from `public/draco/`. Off-screen viewers are skipped.
- `src/turntable.ts` (`Turntable`) is the shared base for the CSS 3D objects in game and app cards (CSS 3D rather than three.js, so text stays DOM): it spins the object, handles drag, and owns the open card's media (the trailer `<video>`, muted by default with an optional sound button, or a `gallery` slideshow when there's no trailer). A shared `gsap.ticker` callback rescales each visible object to its viewer every frame, which is how it follows the card's Flip animation. `open()` starts the media inside the click (so sound is allowed once turned on). An object with a `screen` (the phone) turns to face you and zooms until the screen covers the viewer, compensating for perspective, then the media takes over; the viewer gets the screen's corner radius via `--screen-r` and clips. Otherwise (the CD case) it cross-fades into the media. `close()` reverses it; `main.ts` calls both from `setOpen`. Geometry is in units, one unit = `--u` in CSS = `U` in TS; keep them in sync. Don't put `opacity`, `filter` or `overflow` on `preserve-3d` containers (`.cd-spin`, `.cd-slab`, `.ph-spin`): that flattens the 3D.
- `src/games.ts` + `src/cdcase.ts`: gamedev content (`Game`: cover, back-cover copy, trailer or gallery, case colour; files in `public/games/<id>/`) and the jewel case (142 x 125 units, a real case in mm). `portrait: true` marks a vertical phone trailer, which `.card--portrait` lays out beside the text (stacked and height-capped on narrow screens).
- `src/apps.ts` + `src/phone.ts`: mobile app content (`App`: screenshot on the phone's screen, vertical recording, body colour; files in `public/apps/<id>/`) and the phone. Its measurements are passed to CSS as variables, and the screen has the recordings' 592 x 1296 shape so the zoom lines up; app cards always use the portrait layout. Games and apps show in array order, not by date.
- `src/main.ts` open/close logic (`setOpen`): GSAP Flip animates cards, dates and viewers, but the `.card-body` text block is deliberately *not* flipped (that would re-wrap text every frame). It is pinned absolutely at its final position/width and slid from its old offset instead. Grid heights are held by easing `min-height` from a plain tween, set before `Flip.from`. Never let a grid lose its height mid-transition (a CSS tween briefly clears the inline value on start), or the page shortens and the browser clamps the scroll position. And don't pin `height` instead: Flip records the end layout at that moment, and a fixed grid height squashes the open card's row (cards are `overflow: hidden`, so their row may shrink). The open card spans the full grid width and stays in its original row via the `--open-row` CSS variable set on the grid (not the card, because Flip clears the card's inline styles). Window scroll is tweened alongside. Interrupted animations are killed and restarted from current positions. Open state is mirrored to the URL hash (`/#axis-x` deep-links to a card), and each open is counted in GoatCounter (script in `index.html`) as a `/#id` page view. `prefers-reduced-motion` makes durations 0 and stops the turntable.
- A drag on a viewer spins the model, case or phone, and `main.ts` suppresses the click that would otherwise toggle the card. Clicks inside an open card only close it from the viewer or ✕, so text stays selectable.
- `src/squiggle.ts`: seeded-PRNG hand-drawn SVG zigzag, redrawn only when the viewport width changes.

## Assets and legacy paths

- Trailers and app recordings are H.264 MP4 (no ffmpeg here; macOS `avconvert -p Preset1280x720` works, though phone recordings that are already H.264 with `moov` before `mdat` are smaller left as they are). They load only when the card is hovered or opened.
- `public/models/*.glb` are Draco-compressed copies. The source CAD exports (`.fbx` etc.) live in `/Assets/`, which is gitignored. Compress with Draco only; never decimate/simplify meshes.
- Keep these at their existing URLs: `/assets/Abinav_Pallathoor_CV.pdf`, `/app-ads.txt`, `/googlee03674d1f2e23b86.html`, and the `google-site-verification` meta tag in `index.html`.
